DOCUMENT R11 — Rail performance records, 9 August 2019: delay attribution and periodic statistics
Owner/originator: Network Rail Infrastructure Ltd (historic delay attribution data, PSS extract;
glossary; explanation document); Office of Rail and Road (data portal periodic tables, source
Network Rail)
Record type: real Network Rail delay-attribution records for selected incidents of 9 August 2019
with the publisher's code glossary, and ORR periodic tables of trains planned, cancellations and
severely disrupted days
STATUS: REAL DATA EXTRACTS — dataset values, identifiers and publication dates are unchanged from
the publishers' files (only rows and columns were selected). Nothing in this record is
synthesised; it computes no totals other than the size of the selection described in Part A.
Clock reference: Network Rail date-times are written dd/mm/yyyy HH:MM (dates dd-Mon-yy); the file
and its explanation document state no time zone. ORR tables are by railway period (four-week
periods; Part B gives Network Rail's period end dates).
Value-status legend: [measured] metered or observed value as published; [reported] value, time or
statement given by its publisher or by a report; [estimated] value its source describes as an
estimate; [modelled] value produced by a model; [digitised] and [illustrative] are not used.

    falls on 09/08/2019 and whose incident_reason is XK or whose resp_manager is METR (codes

    responsible manager METR) and 3234 records, counted for this record. No other incident of the
    period is included.
    File R11_networkrail_delay_records_selected_incidents.csv [reported]: one row per record (one
    train, one delay or cancellation event), in the publisher's order, 18 of the 40 published
    columns: incident_number, origin_departure_date, trust_train_id, toc_code, unit_class,

    incident. Values are as published (blank where the publisher's cell is blank).
A2   Network Rail, 'Explanation document: Historic attributed delays' (May 2021), quoted:
    "The data contains both delay and cancellation events (denoted by the performance event code)
      and a user should be careful when summing delay minutes (pfpi minutes) to exclude
      cancellation events."
    "It is possible that the detailed reasons for some of the delays in this file are still being
      investigated and until this is complete the responsibility for the delay is still not
      finalised (see attribution status)."
    "Delay data is remapped to reflect the franchise mapping at the time of the data extraction
      (in this case May 2021)."
    "trainids are unique within a railway period but not within a year"
    "Train schedule type / traction type/ trailing load / unit class – these aren’t mandated or
      validated fields within PSS"
    "Incident number – the TRUST DA incident number (not unique without the create date)"
    "Incident create date – the date the incident was entered into the system"
    "Incident start/end date – the date the system has the incident live (this is not the length
      of the incident on the ground)"
    "Responsible Manager – who within the industry is responsible for the delay – all delays have
      responsibility for performance improvement purposes"
    "Incident Reason – the Delay Attribution Guide cause code for the incident"
    "Incident equipment – internal free form information"
    "Incident description – short description of the incident for internal use"
    "If no code the delay is primary (ie the delay is at the site of the incident) if reactionary
      the delay is a later consequence of that incident"
    "A and M denote delays, C, D, O, P, S and F are cancellations … C – is a full cancelletion, D
      is a diversion, F is a failure to stop, S is a scheduled cancellation and O/P are part
      cancellations"
    "Start/end stanox – the location of the delay (not the incident)"
    "Event Datetime – the time the train encountered the delay"
    "Pfpi minutes – the size of the delay …. Note if the train is cancelled (performance event
      code) a deemed delay minute is generated for internal usage in these circumstances the train
      hasn’t been delayed and including this delay in any calculation of delay is misleading."
    "Applicable timetable flag – if N the train is not in official performance records as it is a
      short term replacement of a train plan – normally a reinstatement of part of a cancelled
      service"
